# Atuin 18.23.0 alignment — 2026-10-01

## Baseline and cause

The host's Home Manager Atuin client/daemon and the NixOS Atuin sync server are
owned by `nix-meta`. Its flake input was pinned to 18.18.1, while Pytuin's
development shell already supplied 18.23.0. A 18.23.0 status probe had
forward-migrated the user's real history database with migration
`20260818000000`; the 18.18.1 daemon then failed on startup because that
migration was absent from its resolved migration set. The active socket
continued accepting clients while systemd restarted the daemon.

Observed before deployment on 2026-10-01: `atuin-daemon.socket` was active at
`/run/user/1000/atuin.sock`; `atuin-daemon.service` repeatedly exited with
status 1, had 1,238 restarts, and invoked the old 18.18.1 store path. Both
Nix-evaluated Home Manager client and server package versions resolve to
18.23.0 after this change. No command modifies or replaces the history
database.

## Change

- Pin `inputs.atuin` to v18.23.0 and update `flake.lock` to release commit
  `78366dca8c4941731e06a2f81c0980cc2ccc3836`.
- Set both Home Manager package metadata overrides to 18.23.0. They keep the
  package selected by the client, daemon, shell initialization, PTY proxy, and
  server on one derivation/version.
- Enable Atuin's opt-in `output.enabled` setting so the daemon stores output for
  Atuin's native `atuin output` search; the latest release does not enable
  capture by default.
- Update the Atuin Codex hook compatibility comment. Its current payload
  normalization remains in place.
- Keep the existing Home Manager zsh initialization ordering: Atuin's
  `pty-proxy init zsh` is evaluated before atuout's hook, while the normal
  Atuin zsh history integration is emitted by nix-terminal. Both now resolve
  the pinned package through `programs.atuin.package`.

## Release evidence

- [Atuin v18.23.0 GitHub release](https://github.com/atuinsh/atuin/releases/tag/v18.23.0)
  identifies commit `78366dc` and labels 18.23.0 latest stable as checked on
  2026-10-01.
- [Atuin issue #3382](https://github.com/atuinsh/atuin/issues/3382) describes
  the older-daemon/newer-database compatibility failure mode.
- [Atuin PR #4173](https://github.com/atuinsh/atuin/pull/4173) added clearer
  diagnostics for version mismatch/downgrade cases.
- [Atuin 18.22.0 release](https://github.com/atuinsh/atuin/releases/tag/v18.22.0)
  introduced native output storage/search and replaced the earlier Semantic
  capture API.

## Verification

Nix evaluation confirms both configured package versions are `18.23.0`, and
the `server` toplevel build succeeded. User-scope Home Manager activation
installed 18.23.0 and the explicit output-capture setting. The differing
preexisting `~/.codex/hooks.json` was preserved at
`~/.codex/hooks.json.pre-atuin-20261001` before Home Manager installed its
managed link.

After activation, the user daemon is running Atuin 18.23.0 (protocol 3),
`atuin history start` exits 0 within its 8-second bound, the socket is active
with zero queued connections, and the daemon has no restart loop. `pytuin
status` reports the daemon and sync server reachable; `pytuin doctor` exits 0.
An interactive PTY zsh session ran multiple commands and exited 0. The zsh
configuration has one `pty-proxy init`, one `atuin init`, and one
`_atuin_preexec` hook.

Native output capture is verified: an interactive command's output was found
by `atuin output search` with its history ID. The separate `atuout` archiver
still reports `capture: no` because it probes the pre-18.22 Semantic gRPC API;
Atuin 18.23 stores/searches output natively. Its existing store remains
available, but it did not harvest the new native capture.

The NixOS system generation is built but not activated. The current user has no
cached sudo credentials, so the system-level Atuin sync server remains on
18.18.1 until an administrator runs:

```sh
sudo /run/current-system/sw/bin/nixos-rebuild switch --flake /home/andrew/Documents/Projects/nix-meta#server
```

That activation should take a few minutes because the updated system closure is
already built. No database deletion, downgrade, or replacement was performed.

Build logs are captured under `/tmp/atuin-upgrade-20261001T1530Z/build.log` and
`/tmp/atuin-upgrade-20261001T1551Z/build.log`; Home Manager activation and PTY
output are alongside them.
